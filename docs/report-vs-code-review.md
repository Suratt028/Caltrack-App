## B. ข้อความที่ขัดกับโค้ด

1. **"เข้ารหัสรหัสผ่านด้วย Bcrypt"** (บทที่ 4, TC-01) → โค้ดใช้ **scrypt**
2. **"JWT" / "JSON Web Token"** (ตาราง 1.1, 4.1, TC-02, TC-15) → เป็นโทเคน HMAC ที่เขียนเอง ไม่ใช่ JWT ถ้าจะเขียนว่า JWT ต้องอธิบายว่า "คล้ายแนวคิด JWT" หรือไม่ก็เปลี่ยนโค้ดไปใช้ JWT จริง (`jose` ติดตั้งอยู่แล้ว)
3. **"Jest ร่วมกับ Supertest", "Postman"** (4.1) → การทดสอบจริงใช้ **`node --test`** (ตัวทดสอบที่มากับ Node.js) ร่วมกับ **mongodb-memory-server** มี 6 ไฟล์ ประมาณ 39 test case (api, rate limit, food matching, Gemini error/fallback, nutrition math)
4. **บัญชี local/offline** (3.1.1.4, 3.1.2) → ปัจจุบันสร้างบัญชี local ไม่ได้แล้ว การสมัครและเข้าสู่ระบบต้องผ่าน backend โค้ดเหลือแค่ส่วนรองรับบัญชีเก่าที่ขึ้นต้นด้วย `local_` (`AppContext.js:60`) ควรตัดย่อหน้านั้นออก หรือเขียนว่าเป็นข้อจำกัดของบัญชีรุ่นเก่า
5. **Socket.io, Cloudinary, Google Maps, Push Notification, แชท, ระบบจับคู่, Cosine Similarity** (สารบัญบทที่ 2, บทที่ 3–5, ภาคผนวก) → **ไม่มีในโค้ด** ให้ลบออกทั้งหมด
6. **2.5.15** อ้างถึง "1.4.1 ข้อ 7" ว่าเป็นเรื่องแจ้งเตือน (และพิมพ์ผิดเป็น "เฟีเจอร์เบื่อ") → ข้อ 7 คือ backend และแอปยังไม่มีการแจ้งเตือนมื้ออาหาร ควรเขียนเป็นข้อเสนอแนะใน 5.4 แทน

## D. ข้อมูลฐานข้อมูลจริง (ใช้กับ 1.4.2, ตาราง 1.1, 3.2.3, 3.3.4)

คอลเลกชันใน MongoDB (`server.js:166-327`):

| คอลเลกชัน | เก็บอะไร |
|---|---|
| `users` | อีเมล, รหัสผ่าน (scrypt), googleId, appleId, displayName, role (user/admin) |
| `profiles` | เพศ, อายุ, ส่วนสูง, น้ำหนัก, ระดับกิจกรรม, เป้าหมาย, น้ำหนักเป้าหมาย, เป้า kcal/โปรตีน/คาร์บ/ไขมัน |
| `logs` | บันทึกอาหารรายการต่อรายการ (userId, dateKey, entry) |
| `user.foods` | สำเนาสำหรับรายงาน: ชื่ออาหาร, kcal, โปรตีน, คาร์บ, ไขมัน, ใยอาหาร, น้ำตาล, โซเดียม, แหล่งที่มา |
| `weightLogs` | น้ำหนักรายวัน (1 ค่าต่อวัน) |
| `foods` | ฐานข้อมูลอาหารไทย ค่าต่อ 100 กรัมของส่วนที่กินได้ (โครงสร้างยืดหยุ่น) |
| `scanImages` | รูปสแกน (เฉพาะเมื่อผู้ใช้ยินยอม) |
| `scanLogs` | ประวัติการสแกนสำหรับแอดมิน: โมเดล, สถานะ (success/low_conf/no_food/failed), latency, tokens |
| `appSettings` | ค่าที่แอดมินตั้ง (โมเดลและ prompt ของ AI, โควตาสแกน, โหมดปิดปรับปรุง) |
| `tickets` | เรื่องที่ผู้ใช้แจ้งปัญหา (Open / In Progress / Resolved) |
| `oauthTickets` | ตั๋วชั่วคราวของ Apple Sign In (หมดอายุอัตโนมัติ) |

**จำนวนรายการอาหาร:** ในฐานข้อมูลตอนนี้ประมาณ 1,167 รายการ (ตามคอมเมนต์ใน `server.js:321`) ชุดใหม่ `thaiFoods_final.json` มี **1,194 รายการ** (ตารางอาหารไทย + INMU + USDA 43 รายการ) แต่ **ยังไม่ได้อัปโหลด** (`reports/food-final-report.md`) ให้เลือกตัวเลขตามสิ่งที่อยู่ในฐานข้อมูลตอนส่งเล่ม

## E. จุดเล็ก ๆ อื่น

- หัวข้อในบทที่ 1 ไม่ตรงกับสารบัญ: เนื้อหามี 1.2 ปัญหาที่ต้องแก้ / 1.3 วัตถุประสงค์ / 1.4 ขอบเขต แต่สารบัญเป็น 1.2 วัตถุประสงค์ / 1.3 ขอบเขต, ใต้ 1.4 ยังพิมพ์ว่า "1.3.2 ขอบเขตด้านเนื้อหา" (ควรเป็น 1.4.1) และ 1.4.3 ข้ามจาก 1.4.3.1 ไป 1.4.3.3
- 1.6.4.1 อ้าง "เกณฑ์ในหัวข้อ 4.4" แต่บทที่ 4 มีถึง 4.3 ส่วน 2.5.4 อ้าง "หัวข้อ 3.8" ซึ่งไม่มี
- 1.1 พิมพ์ผิด "ก่วยเตี๋ยว" → "ก๋วยเตี๋ยว"
- บทคัดย่อและคำนำยังมี `[มหาวิทยาลัย]` / `[คณะ/มหาวิทยาลัย]` ให้ใส่ "คณะวิทยาศาสตร์และเทคโนโลยี มหาวิทยาลัยราชภัฏสวนสุนันทา"
- กิตติกรรมประกาศ: "ขอขอบพระคุณ กัลยณัฏฐ์" ขาดคำนำหน้า "ดร."
- ท้าย 2.5 ยังมี "[หมายเหตุ] ใส่งานวิจัยจริงแล้ว 1 เรื่อง…" ซึ่งล้าสมัยแล้ว ให้ลบ
- 2.5.5 และ 2.5.5.7 ยังติดป้าย "ยังไม่ได้เปิดอ่านต้นฉบับ" ต้องตรวจก่อนส่ง
- ที่มาของตาราง 1.1 ยังเป็น `([ชื่อผู้จัดทำ], 2569, หน้า [เลขหน้า])`
- 3.1 ใช้คำว่า "คณะผู้จัดทำ" แต่โครงงานนี้ทำคนเดียว ควรใช้ "ผู้จัดทำ"
