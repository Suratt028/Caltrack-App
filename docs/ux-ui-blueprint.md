# CalTrack — UX Strategy & UI Blueprint

> เอกสารนี้ตอบ prompt "Senior Product Designer" โดยเติม context จากตัวแอปจริง (React Native + Expo, backend Express/MongoDB, สแกนด้วย Gemini Vision, ฐานข้อมูลอาหาร INMU/กรมอนามัย) และยึด design language เดิมใน `docs/figma-uxui-prompt.md` ไม่ได้ออกแบบใหม่ทั้งหมด

## 0. Context ที่ใช้

| หัวข้อ | ค่าที่ใช้ |
| --- | --- |
| ผลิตภัณฑ์ | CalTrack แอปนับแคลอรี่ภาษาไทย บันทึกอาหารไทยด้วยการค้นหาหรือถ่ายรูปให้ AI ประเมิน |
| กลุ่มเป้าหมาย | คนทำงาน/นักศึกษาไทยอายุ 20–40 ปี กินข้าวนอกบ้านเป็นหลัก อยากคุมน้ำหนักแต่ไม่อยากชั่งอาหาร |
| Pain points | แอปต่างประเทศไม่มีเมนูไทย, ไม่รู้ว่า "1 จาน" กี่กรัม, บันทึกทีละรายการช้าจนเลิกใช้ภายในสัปดาห์แรก, ตัวเลขเยอะจนไม่รู้ว่าวันนี้ "โอเค" หรือไม่ |
| Business goal | (1) ผู้ใช้ใหม่บันทึกมื้อแรกสำเร็จภายใน 2 นาทีหลังสมัคร (2) บันทึกหนึ่งมื้อได้ภายใน 30 วินาที (3) เพิ่ม Day-7 retention |
| แพลตฟอร์ม | iOS / Android (หลัก), Expo Web responsive, Admin web console |

## 1. User Persona & Jobs-to-be-Done

### Persona หลัก — "มิ้น" 27 ปี พนักงานออฟฟิศ กรุงเทพฯ
- กินข้าวกล่อง/ร้านตามสั่งวันละ 2 มื้อ ชาไข่มุกสัปดาห์ละ 3 แก้ว
- อยากลด 4 กก. ก่อนงานแต่งเพื่อน เคยโหลดแอปต่างประเทศแล้วเลิกเพราะหา "ข้าวมันไก่" ไม่เจอ
- ใช้มือถือมือเดียวระหว่างยืนรถไฟฟ้า/ต่อคิวร้านอาหาร
- กลัวการถูกตัดสิน: ถ้าแอปขึ้นสีแดงตอนกินเกิน จะเลิกเปิดแอป

### Persona รอง — "พี่ต้น" 38 ปี เพิ่งตรวจสุขภาพเจอไขมันสูง
- ไม่ถนัดเทคโนโลยี อ่านตัวเล็กไม่ค่อยชัด ต้องการตัวเลขเดียวที่เข้าใจง่าย ("วันนี้เหลืออีกเท่าไร")

### Jobs-to-be-Done
| ประเภท | Job statement |
| --- | --- |
| Functional (หลัก) | เมื่อฉันกำลังจะกิน/เพิ่งกินเสร็จ ฉันอยากบันทึกได้ในไม่กี่วินาที เพื่อไม่ให้การนับแคลอรี่กลายเป็นภาระ |
| Functional | เมื่อฉันตัดสินใจว่าจะกินอะไรมื้อเย็น ฉันอยากรู้ว่าวันนี้เหลือพลังงานเท่าไร เพื่อเลือกเมนูได้เอง |
| Functional | เมื่อจบสัปดาห์ ฉันอยากเห็นแนวโน้มว่ามาถูกทางไหม โดยไม่ต้องอ่านตาราง |
| Emotional | ฉันอยากรู้สึกว่าควบคุมได้ ไม่ใช่รู้สึกผิดเวลากินเกิน |
| Social | ฉันอยากกินกับเพื่อนได้ตามปกติโดยไม่ต้องหยิบตาชั่งออกมา |

### หลักการออกแบบที่ได้ (เข็มทิศ)
1. **ความเร็วมาก่อนความแม่นยำ 100%** — ค่าประมาณที่บันทึกจริงดีกว่าค่าแม่นที่ไม่มีใครบันทึก (แต่ต้องบอกให้ชัดว่าเป็นค่าประมาณ)
2. **ตัวเลขเดียวที่สำคัญ** — "เหลืออีก X kcal" เป็นพระเอกของทุกหน้า
3. **ไม่ตัดสิน** — ไม่มีสีแดงสำหรับการกินเกิน ไม่มี streak shaming
4. **มือเดียวได้** — action หลักอยู่ในครึ่งล่างของจอเสมอ

## 2. Information Architecture & User Flow

### Navigation (bottom tab, 5 ช่อง)
```
หน้าหลัก │ บันทึก │ (◉ สแกน — ปุ่มกลางยกสูง) │ แนวโน้ม │ โปรไฟล์
```
- ปุ่ม **สแกน** อยู่ตรงกลางเพราะเป็นทางที่เร็วที่สุดและเป็นจุดขาย และอยู่ในโซนนิ้วโป้งพอดี
- Desktop/Tablet: sidebar ซ้ายรายการเดียวกัน

### Sitemap
```
Auth
├─ Welcome → สมัคร / เข้าสู่ระบบ / ลืมรหัสผ่าน (รหัส 6 หลักทางอีเมล)
Onboarding (3 ขั้น ข้ามได้)
├─ เกี่ยวกับคุณ → กิจกรรม → เป้าหมาย → สรุปแคลอรี่/มาโคร
Main
├─ หน้าหลัก: ตัวเลือกวัน · Calorie ring · Macro bars · มื้ออาหาร 4 มื้อ (+ ต่อมื้อ)
│   └─ Edit entry (bottom sheet)
├─ บันทึก: เลือกมื้อ · ค้นหา · ล่าสุด/บ่อย · เพิ่มเอง
│   └─ Portion (เลือกปริมาณ → บันทึก)
├─ สแกน: กล้อง/คลังภาพ → วิเคราะห์ → Review (แก้เมนู/ปริมาณ) → บันทึก
├─ แนวโน้ม: 7 วัน/30 วัน/เลือกช่วง · กราฟแคลอรี่ · มาโคร · น้ำหนัก · BMI · ตาราง
└─ โปรไฟล์: เป้าหมาย · ข้อมูลร่างกาย · การแจ้งเตือน · ความเป็นส่วนตัว · ออกจากระบบ
```

### Flow A — ผู้ใช้ใหม่ถึงมื้อแรก (เป้า ≤ 2 นาที)
| ขั้น | หน้าจอ | Happy path | Error / edge path |
| --- | --- | --- | --- |
| 1 | Welcome | กด "เริ่มต้นใช้งาน" | — |
| 2 | สมัคร | ชื่อ อีเมล รหัสผ่าน หรือ Google | อีเมลซ้ำ → "อีเมลนี้มีบัญชีแล้ว · เข้าสู่ระบบ" (ลิงก์พาไปพร้อมกรอกอีเมลไว้ให้) / รหัสไม่ผ่านกฎ → checklist สด / เน็ตหลุด → banner + ปุ่มลองใหม่ ข้อมูลที่กรอกไม่หาย |
| 3 | Onboarding 1–3 | กรอก เพศ อายุ ส่วนสูง น้ำหนัก → กิจกรรม → เป้าหมาย | ค่านอกช่วง (เช่น ส่วนสูง 17) → "ส่วนสูงควรอยู่ระหว่าง 100–250 ซม." ใต้ช่อง / กด "ข้าม" → ใช้หน้าหลักแบบไม่มีเป้า (ดู Home "ไม่มีเป้าหมาย") |
| 4 | สรุป | เห็น "เป้าหมายของคุณ 1,650 kcal/วัน" → "บันทึกมื้อแรก" | กดย้อนกลับ → ค่าเดิมยังอยู่ทุกขั้น |
| 5 | สแกน หรือ ค้นหา | ถ่ายรูป → ยืนยัน → บันทึก | ดู Flow B |
| 6 | หน้าหลัก | ring ขยับ + รายการใหม่ highlight สีมิ้นท์ + toast "บันทึกแล้ว" | — |

### Flow B — สแกนรูป (เป้า ≤ 30 วินาที)
```
กดปุ่มสแกน ─► [ขอสิทธิ์กล้อง?]──ปฏิเสธ──► "เปิดการตั้งค่า" / "เลือกจากคลังภาพ"
     │อนุญาต
     ▼
ถ่าย/เลือกรูป ─► วิเคราะห์ (5–15 วิ, ยกเลิกได้)
     │                     ├─ timeout / server error ─► "ลองอีกครั้ง · เลือกรูปอื่น · ค้นหาเอง"
     │                     └─ ไม่พบอาหาร ─► เดียวกัน + เคล็ดลับถ่ายรูป
     ▼
Review: รายการที่พบ (มีชิป "เมนูที่ใกล้เคียง", ปริมาณ ½ 1 1½ 2, ช่องกรัม)
     │  └─ ความมั่นใจต่ำ ─► บรรทัดสีทอง "AI ไม่แน่ใจ ลองเลือกเมนูที่ใกล้เคียง" + ขยายชิป
     ▼
"บันทึก 2 รายการ · 720 kcal" ─► หน้าหลัก + highlight
```
- กด back ระหว่าง Review → dialog "ทิ้งผลสแกนนี้?" (ทิ้ง / แก้ต่อ) เพราะการสแกนใช้เวลาและโควตา AI

### Flow C — ค้นหาและบันทึก
```
บันทึก (มื้อเลือกอัตโนมัติตามเวลา) ─► ล่าสุด/บ่อย ─► "+" ด่วน ─► snackbar "เพิ่มแล้ว · เลิกทำ"
                                    └► พิมพ์ค้นหา ─► ผลลัพธ์ ─► Portion ─► "บันทึก 1.5 จาน · 840 kcal"
                                                    └► ไม่พบ ─► "ลองสแกนรูป" / "เพิ่มเมนูเอง"
```

### Flow D — ลืมรหัสผ่าน
อีเมล → รหัส 6 หลัก (ช่องแยก 6 ช่อง, วางจากคลิปบอร์ดได้, ส่งใหม่ได้หลัง 60 วิ) → รหัสใหม่ → เข้าสู่ระบบอัตโนมัติ
- Error: รหัสผิด → "รหัสไม่ถูกต้อง เหลือ 4 ครั้ง" / หมดอายุ → "รหัสหมดอายุ · ส่งรหัสใหม่" / ไม่พบอีเมล → ข้อความกลาง ๆ "ถ้ามีบัญชีนี้ เราได้ส่งรหัสไปแล้ว" (กันการสุ่มหาอีเมล)

### Flow E — Session หมดอายุ / ออฟไลน์
- ออฟไลน์: บันทึกลงเครื่องก่อน (AsyncStorage) + banner บาง ๆ ไม่บล็อกการใช้งาน, sync เมื่อออนไลน์
- Session หมดอายุ: dialog เข้าสู่ระบบใหม่ **โดยไม่ล้างข้อมูลที่ยังไม่ sync**

## 3. Wireframe Blueprint & Visual Hierarchy

### 3.1 หน้าหลัก (Home) — หน้าที่เปิดบ่อยที่สุด
```
┌──────────────────────────────┐
│ ‹   วันนี้ · พฤ. 13 พ.ย.   ›   │  ← H3, สลับวัน (swipe ซ้าย/ขวาได้)
│                              │
│        ╭───────────╮         │
│        │  เหลือ     │         │  ← ① Display 32/800 — ตัวเลขเดียวที่สำคัญ
│        │  930       │         │
│        │  kcal      │         │
│        ╰───────────╯         │
│   กินแล้ว 720 · เป้า 1,650     │  ← ② body muted
│                              │
│ โปรตีน ████░░ 42/90 g          │  ← ③ Macro bars (สี + ชื่อเสมอ)
│ คาร์บ  ██████░ 110/180 g       │
│ ไขมัน  ███░░░ 20/55 g          │
├──────────────────────────────┤
│ มื้อเช้า        320 kcal   [+]  │  ← ④ กลุ่มมื้อ, "+" 48dp ชิดขวา (นิ้วโป้งขวา)
│  ข้าวต้มหมู · 1 ถ้วย     320    │
│ มื้อกลางวัน     400 kcal   [+]  │
│  ข้าวกะเพราไก่ · 1 จาน   400    │
│ มื้อเย็น                   [+]  │
│  ยังไม่ได้บันทึก                 │
│ ของว่าง                    [+]  │
├──────────────────────────────┤
│ หน้าหลัก บันทึก (◉) แนวโน้ม โปรไฟล์│
└──────────────────────────────┘
```
**Hierarchy:** ① เหลือกี่ kcal → ② บริบท (กิน/เป้า) → ③ มาโคร → ④ รายละเอียดมื้อ
**ทำไม "เหลือ" ไม่ใช่ "กินแล้ว":** ช่วยตัดสินใจมื้อต่อไป (forward-looking) ตรงกับ JTBD ข้อ 2

## 4. Complete UI States

### หน้าหลัก
| State | การแสดงผล |
| --- | --- |
| Default | ตาม wireframe 3.1 |
| Loading | Skeleton: วงแหวนเทา + 3 แถบมาโคร + 4 แถวมื้อ (shimmer ช้า 1.2 วิ); ไม่ใช้ spinner เต็มจอ ข้อมูลในเครื่องแสดงก่อนแล้วค่อย sync |
| Empty (ครั้งแรก) | 4 มื้อว่างพร้อมปุ่ม "+" + การ์ดคำแนะนำ 1 ใบชี้ไปที่ปุ่มสแกน "ลองถ่ายรูปอาหารมื้อนี้ดู" (ปิดได้ ไม่โผล่อีก) |
| Empty (วันในอดีต) | ภาพประกอบเรียบ ๆ + "ไม่มีบันทึกในวันนี้" + "วันที่ไม่มีบันทึกจะไม่ถูกนับในแนวโน้ม" |
| No goal | แสดง "กินแล้ว 720 kcal" แทน + การ์ด "ตั้งเป้าหมายเพื่อดูพลังงานที่เหลือ" |
| Over goal | วงแหวนเต็มสีทอง, ตรงกลาง "เกินเป้าหมาย 240 kcal", ไม่มีไอคอนเตือน ไม่มีสีแดง |
| Error | sync ไม่สำเร็จ → banner "ซิงก์ไม่สำเร็จ ข้อมูลยังอยู่ในเครื่อง · ลองใหม่" ข้อมูลยังแสดงตามปกติ |
| Offline | banner "ออฟไลน์อยู่ บันทึกไว้ในเครื่องก่อน จะซิงก์เมื่อออนไลน์" |
| Success | หลังบันทึก: แถวใหม่ highlight มิ้นท์ 1.5 วิ + ring animate 400ms + toast สั้น |

### สแกน
| State | การแสดงผล |
| --- | --- |

### 5.3 Accessibility (WCAG 2.2 AA)
- **Contrast:** ข้อความ ≥ 4.5:1 (ink บน bg ≈ 11:1, inkMuted ≈ 5.3:1); กราฟิก/เส้นกราฟ ≥ 3:1; ข้อความสีทองใช้ #8A611F เสมอ
- **ไม่ใช้สีอย่างเดียว:** มาโครมีชื่อ, error มีไอคอน + ข้อความ, แท่งวันนี้ใช้เส้นประ + ป้าย "ยังไม่ครบ"
- **Touch target:** ≥ 44×44pt / 48×48dp, ระยะห่างระหว่าง target ≥ 8
- **Screen reader:** ring อ่านเป็นประโยคเดียว "เหลือ 930 กิโลแคลอรี่ จากเป้าหมาย 1,650"; กราฟมี `accessibilityLabel` สรุปค่า + ตารางข้อมูลด้านล่างเป็นทางเลือก; ปุ่ม "+" อ่านว่า "เพิ่มอาหารมื้อเช้า"; toast/snackbar ใช้ `accessibilityLiveRegion="polite"`
- **Keyboard (web/ต่อคีย์บอร์ด):** tab order บนลงล่างตาม visual, focus ring 2px primary มองเห็นชัด, Esc ปิด sheet/dialog, focus กลับไปที่ปุ่มที่เปิด
- **Dynamic Type:** รองรับขยายถึง 200% โดย layout ไม่ตัดคำ (ring ย่อ label ก่อนตัวเลข)
- **ฟอร์ม:** label อยู่นอกช่องเสมอ (ไม่ใช้ placeholder แทน label), `keyboardType="numeric"` สำหรับตัวเลข, หน่วยอยู่ในช่อง
- **Time limits:** snackbar undo 5 วิ แต่หยุดนับเมื่อ screen reader เปิดอยู่

## 6. UX Rationale & Friction Reduction

| หลักการ | นำไปใช้ที่ | ผลที่ต้องการ |
| --- | --- | --- |
| **Fitts's Law** | ปุ่มสแกนใหญ่ตรงกลางล่าง, CTA sticky เต็มความกว้าง, "+" ชิดขวา | กดเร็วด้วยนิ้วโป้ง มือเดียว |
| **Hick's Law** | Portion มีแค่ 4 ชิป (½ 1 1½ 2) + ช่องกรัมเป็นทางเลือก; onboarding กิจกรรม 4 ตัวเลือก | ตัดสินใจเร็ว ไม่ต้องคิดเป็นกรัม |
| **Progressive Disclosure** | "ข้อมูลต่อ 100 กรัม" ซ่อนไว้, onboarding 3 ขั้นแทนฟอร์มยาว, ไฟเบอร์/โซเดียมไม่อยู่หน้าแรก | มือใหม่ไม่ล้น ผู้ใช้ขั้นสูงยังเข้าถึงได้ |
| **Recognition over Recall** | แท็บ ล่าสุด/บ่อย, ชิป "เมนูที่ใกล้เคียง", มื้อเลือกอัตโนมัติตามเวลา | คนไทยกินซ้ำสูง — ลดการพิมพ์ |
| **Sensible Defaults** | ปริมาณเริ่มที่ 1 จาน, quick "+" ใช้ปริมาณครั้งก่อน | บันทึกได้ใน 1 แตะ |
| **Forgiveness (Undo > Confirm)** | ลบ/เพิ่ม ด้วย snackbar เลิกทำ; ยืนยันเฉพาะสิ่งที่ย้อนไม่ได้ (ลบบัญชี, ทิ้งผลสแกน) | ลดขั้นตอน แต่ปลอดภัย |
| **Goal-Gradient Effect** | "บันทึกอีก 2 วันเพื่อดูแนวโน้ม", progress dots ใน onboarding | กระตุ้นให้ทำจนครบ |
| **Peak-End Rule** | จบการบันทึกด้วย highlight มิ้นท์ + ring เคลื่อนไหว | จบด้วยความรู้สึกดี → กลับมาใช้ซ้ำ |
| **Loss aversion แบบไม่ลงโทษ** | ไม่มี streak, ไม่มีสีแดงเมื่อกินเกิน, วันว่างไม่ถูกนับในแนวโน้ม | ลดความรู้สึกผิดซึ่งเป็นสาเหตุหลักของการเลิกใช้แอปลดน้ำหนัก |
| **Trust calibration** | "≈" + แท็กค่าประมาณ, บอกให้แก้ผล AI ได้, เครดิตแหล่งข้อมูล INMU | ผู้ใช้เชื่อในระดับที่เหมาะสม ไม่เชื่อ AI 100% |
| **Value before commitment** | (ข้อเสนอ) ให้สแกนลองได้ 1 ครั้งก่อนสมัคร | เห็น "aha moment" ก่อนกรอกข้อมูล → เพิ่ม signup conversion |

### Edge cases การใช้งานจริง
- **กดย้อนกลับ:** ทุกฟอร์มเก็บค่าที่กรอก; Review สแกน/Portion ที่แก้ไขแล้วถาม "ทิ้งการเปลี่ยนแปลง?"; Android back ปิด sheet ก่อนออกจากหน้า
- **กรอกผิด:** ตัวเลขรับเฉพาะ numeric, ช่วงสมเหตุสมผล (น้ำหนัก 25–300 กก.), ค่าแปลก (กรัม > 2,000) ถามยืนยันแทนการบล็อก
- **บันทึกย้อนหลัง:** เปลี่ยนวันจาก Home แล้วกด "+" บันทึกเข้าวันนั้น; Portion แก้เวลาได้
- **บันทึกซ้ำโดยไม่ตั้งใจ:** ปุ่มบันทึก disabled หลังกด + idempotency ฝั่ง backend
- **เน็ตช้า/หลุดกลางสแกน:** เก็บรูปไว้ ลองใหม่ได้โดยไม่ต้องถ่ายใหม่
- **มือเดียว:** ไม่มี action หลักในแถบบน 1/4 ของจอ; ปุ่มย้อนกลับใช้ swipe-back ได้
