# CalTrack · UX audit (ตุลาคม 2569)

Audit of the Expo / React Native Web app on `main` (b17026e) against the
design handoff PDFs (*Thai implementation handoff*, Home, Food search, Portion,
AI capture → analyzing → review → recovery, Trends, empty states).
Priority: **P0** blocks or misleads users · **P1** hurts a core flow ·
**P2** inconsistency / polish that users notice · **P3** nice to have.

| # | Problem | Impact on users | Fix | Pri |
|---|---------|-----------------|-----|-----|
| 1 | Tablet and desktop web reuse the phone layout: a bottom tab bar stretched to 1,120 px with icon and label side by side, the Scan FAB overlapping the "สแกน" label, and one long column of cards. | On the web the app looks broken and wastes space; the nav is hard to scan. The handoff asks for top nav on tablet and a side nav + multi-column dashboard on desktop. | Responsive shell: bottom tabs < 600 px, top nav 600–1,023 px, side nav ≥ 1,024 px. Home and Trends get two-column layouts on wide screens. | P0 |
| 2 | Home has no way to start logging. Logging lives only in the tab bar ("บันทึก" and a floating camera). | The most frequent task needs the user to know the tab icons. The handoff puts "บันทึกอาหาร" and "สแกนอาหารด้วย AI" right under the energy card. | Primary + secondary CTAs on Home; a "มื้อต่อไป" card on wide screens; empty meal slots ("มื้อเย็น · ยังไม่มีรายการ  +") open Log with that meal. | P0 |
| 3 | The AI scan screen mixes a database search box, the camera hero, a consent switch, the library button and the review all on one scroll; analyzing, error and success are small cards appended below the photo. | Users don't know which step they are in; the error state is a red banner with "สแกนใหม่", no path to log manually; there is no way to cancel an analysis. | Explicit flow: capture → analyzing (cancellable) → review → saved, plus a recovery screen with "ลองประเมินภาพเดิมอีกครั้ง / เลือกรูปอื่น / ค้นหาและบันทึกอาหารเอง". | P0 |
| 4 | Scan is a centre tab with a raised FAB, but the handoff's tab bar has four tabs (หน้าหลัก · บันทึกอาหาร · แนวโน้ม · โปรไฟล์) and treats scan as a step inside logging with a back button. | Five tabs crowd 375 px (labels at 11 px); the FAB covers content and is inconsistent with Portion, which is already a pushed flow screen. | Scan becomes a stack flow screen (with back) reached from Home, Log (camera button in the search field) and recovery. URL `/scan` still works. | P1 |
| 5 | Ring centre shows "1000" without a thousands separator and the over-goal state shows the excess as if it were remaining. Macro rows read "56/110 g · 51%". | Numbers are harder to read; "g" and "%" mix English into Thai UI; over-goal is easy to misread. | Ring: "เหลืออีก / 1,000 / กิโลแคลอรี", over goal "มากกว่าเป้า / X / กิโลแคลอรี" on a full ring. Macros: dot + name, "56 กรัม", bar, "จาก 110 กรัม". | P1 |
| 6 | Trends shows the mobile summary card **and** three stat cards at every width, so the daily average appears twice on a phone. | Repetition pushes the charts below the fold and reads like a scoreboard. | Phone: one mint summary card. Desktop: three stat cards in a row, charts side by side. | P1 |
| 7 | "ยังมีข้อมูลไม่พอ" always adds "ช่วงนี้ยังไม่มีวันที่บันทึก", even when 1–2 days are logged; the CTA always says "มื้อแรก". | The copy is wrong for anyone who already logged a day. | Copy depends on the number of logged days in the range; CTA "บันทึกอาหารเพิ่ม" when some days exist. | P1 |
| 8 | Food search has no loading skeleton, no recent foods before typing, rows are not tappable (only the 44 px "+"), and "no results" has no actions. | Slow networks look frozen; people re-type the same dishes every day; misses on the small target. | Skeleton rows, "เมนูที่บันทึกล่าสุด" from the user's own logs (opens Portion by foodId), whole-row press, query highlight, empty state with "ล้างคำค้น" / "เพิ่มเมนูเอง". | P1 |
| 9 | Portion: macros as "P 48g · C 108g · F 24g", no quick amounts, meal picker lives inside a card with the unit picker, no confirmation after saving. | Abbreviations aren't Thai-friendly; extra taps for common amounts; after saving the user lands on Home with no feedback. | Mint result card with macro trio + per-100 g detail, quick chips ½ · 1 · 1½ · 2, back button in the header, success banner on Home after saving. | P1 |
| 10 | Hardcoded styles: font sizes 11–42 with ad-hoc line heights, inline styles in ScanScreen/RootNavigator, three different secondary-button looks (outline, dashed, mint). | Thai text with tone marks clips when line height is missing; screens drift apart. | Tokens for type scale (with Thai line heights), spacing, radii, elevation, layout breakpoints; shared `Screen`, `IconButton`, `SectionHeader`, `PrimaryButton` variants (solid / soft / outline / ghost). | P2 |
| 11 | Meal label "มื้อเที่ยง" vs handoff "มื้อกลางวัน"; Scan uses chips for meal while Log/Portion use a segmented control. | Inconsistent vocabulary and controls between steps of the same flow. | One meal vocabulary (เช้า · กลางวัน · เย็น · ว่าง) and the segmented control everywhere. | P2 |
| 12 | Home no-goal state is close to the design but still shows the day switcher above it and lacks the "ตั้งเป้าหมายเพื่อดูพลังงานที่เหลือ" explainer inside the energy card; the empty food list shows four empty meal headers. | First-run screen feels busy. | Header "เริ่มต้นไปด้วยกัน", mint welcome card, energy card with explainer, single "มื้อแรกของวันนี้ เริ่มได้เลย" empty card. | P2 |
| 13 | Icons are 18–20 px with some targets below 44 px (Banner close, date arrows at 44 but the "กลับไปวันนี้" link is 32 px). | Hard to hit on phones. | `IconButton` enforces 44×44; links get `minHeight: 44`. | P3 |
